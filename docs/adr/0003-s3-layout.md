# ADR-0003: S3 は用途ごとに3つのバケットに分け、スナップショットは日付のパーティションで残す

- 日付: 2026-10-01
- 状態: 承認

## 背景

- clips.db は「今の状態」しか持たない。`status` などは上書きされるため、「いつ POSTED になったか」といった履歴はどこにも残らない
- S3 に置くものは、Terraform の state、データ（生データと変換後のデータ）、Athena のクエリ結果の3種類
- Athena は、読んだデータ量で課金される。日付で絞り込んだときに、該当する日のデータだけを読ませたい
- clips.db は約 740KB で、毎日残しても年に数百 MB にしかならない

## 決定

### スナップショットは日付ごとに残す

- 上書きせず、取得した日ごとに残す。日ごとの差分から、状態の変化の履歴を後から復元できるようにする
- 日付は Hive 形式のパーティション（`snapshot_date=YYYY-MM-DD/`）で表す。Athena は `snapshot_date` を列として扱い、`WHERE snapshot_date = ...` で該当するプレフィックスだけを読む
- 同じ日に再実行した場合は、同じパーティションを上書きする（冪等にする）
- 毎回 DB 全体を取る（全量スナップショット）。変わった行だけを取る増分取り込みや、変更ログを拾う CDC は使わない
  - 理由: clips.db は約 740KB と小さく、全量でも負担にならない。全量なら「どの行が変わったか」の判定が不要で、削除された行も取りこぼさない
  - clips.db が更新されても、過去の日付のパーティションは書き換えない。更新後の状態は、次のスナップショットで新しいパーティションとして加わる
  - 限界: 1日1回なので、1日のうちに2回以上変わった場合、途中の状態は残らない。今回の分析（候補スコアと維持率の関係）には影響しないため受け入れる

### バケットは用途ごとに3つに分ける

| バケット | 中身 | 主な設定 |
|---|---|---|
| tfstate | Terraform の state | ADR-0001 のとおり |
| data | `raw/`（取ってきたまま）と `curated/`（変換後） | バージョニングを有効にする |
| athena-results | Athena のクエリ結果 | ライフサイクルで古い結果を自動削除（7日、仮） |

分ける理由:

- **権限の境界**: Athena でクエリするだけの利用者に state を読ませない。バケット単位で分けると、ポリシーが単純になり間違えにくい
- **バケット全体にかかる設定を用途ごとに変える**: 消えては困るもの（state、data）にはバージョニングや `prevent_destroy` をかけ、一時的なもの（Athena の結果）は自動で消す
- **事故の被害範囲を限る**: 1つのバケットの設定を誤っても、ほかの用途に波及しない

### data バケットの中の置き方

```
raw/clips_db/snapshot_date=YYYY-MM-DD/clips.db
curated/clips_db/<テーブル名>/snapshot_date=YYYY-MM-DD/part-0.parquet
```

- `raw/` は一度置いたら書き換えない。`curated/` は `raw/` から何度でも作り直せる
- 今後の取り込み（YouTube Analytics API、Reporting API）も、`raw/<取り込み元>/` の下に同じ規則で置く

## 検討した選択肢

- **スナップショットを上書きする**: 不採用。履歴が残らず、分析基盤を別に建てる理由の1つ（履歴を持つこと）が失われる
- **日付をファイル名に入れる（`clips/2026-10-01.parquet`）**: 不採用。Athena は日付で絞り込めず、毎回すべてのファイルを読む
- **1つのバケットにまとめ、プレフィックスで分ける**: 不採用。ライフサイクルはプレフィックス単位でもかけられるが、権限とバケット全体の設定を用途ごとに分けにくい
- **raw と curated を別バケットにする**: 今は採用しない。両方を読み書きするのが同じ主体で、分けても守れるものが増えない。curated だけを見る利用者ができたら見直す

## 結果

- Athena で、最新の日だけ（`max(snapshot_date)` で絞る。ビューにしておく）も、全期間の推移も扱える
- 状態の変化の履歴は、日次スナップショットの差分として後から作れる（フェーズ2の dbt snapshot で扱う）
- バケットは3つになるが、いずれも MB 単位なので月額は合計 $0.01 未満

## 残る課題

- test-app の `data/clips.db.bak.*`（2026-07-02〜09-06、15個）を、過去の日付のスナップショットとして取り込むか。取り込む場合、`snapshot_date` にはバックアップを取った日を入れる
- バケット名の付け方（アカウントIDを入れない方法）は ADR-0001 の残る課題と合わせて決める
- Athena にパーティションを認識させる方法は、論点5（テーブル定義の管理）で決める
